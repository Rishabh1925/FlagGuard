First time here? Follow the checkout experiment

The situation: a team is testing a new checkout (Variant B) against the existing checkout (control). FlagGuard watches for errors and slow responses, then disables the new rollout if a problem lasts long enough.

  1. Start healthy. Both versions should have enough traffic. Error rate means failed requests; P99 means 99% of measured operations are at or below that duration.
  2. Inject a demo fault. Use the panel next to the guardrails. Only the synthetic demo is affected.
  3. Watch the decision. A brief spike is not enough. The sample gate and sustained-breach timer must pass. Shadow mode records a proposal; enforce mode disables the rollout.
  4. Inspect, then recover. Open the rollback in Recent activity to see the original evidence. Review recovery on the guardrail to stop the demo fault and re-enable.

Verified means Flagsmith's settings were read back. The smoke test separately checks that application requests return to control. No conversion winner is claimed.
